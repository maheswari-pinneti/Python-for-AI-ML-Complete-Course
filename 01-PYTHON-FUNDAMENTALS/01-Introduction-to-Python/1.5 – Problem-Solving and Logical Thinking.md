## 61. Introduction to Computational Thinking

**Computational thinking** is a structured way of understanding problems and designing solutions that can be followed by people or computers.

It helps us turn a complicated problem into clear instructions. Computational thinking is useful in programming, mathematics, science, business, and everyday activities.

It commonly includes four main concepts:

1. **Decomposition:** Breaking a large problem into smaller, manageable parts.
2. **Pattern recognition:** Finding similarities, repeated steps, or common behaviour.
3. **Abstraction:** Focusing on important information and ignoring unnecessary details.
4. **Algorithm design:** Creating an ordered set of steps to solve a problem.

**Example:** Suppose you want to create an application for ordering food. You can divide the task into smaller parts: displaying restaurants, showing menus, adding items to a cart, calculating the bill, accepting payment, and tracking the order.

**Why is it useful?**
- Makes complicated problems easier to understand.
- Helps organise thoughts before coding.
- Reduces unnecessary work.
- Supports clear and reusable solutions.

**Note:** Computational thinking does not mean that you must use a computer to solve every problem. It means approaching problems in a systematic way so that a solution can be clearly explained or programmed.

## 62. What is Problem-Solving?

**Problem-solving** is the process of understanding a problem, identifying the result that is needed, and finding a suitable method to achieve that result.

In programming, problem-solving happens before and during coding. A programmer first understands what the program must do and then plans the instructions.

A general problem-solving process is:

1. Understand the problem.
2. Identify the expected result.
3. Collect the necessary information.
4. Identify inputs and outputs.
5. Divide the problem into smaller tasks.
6. Plan a solution.
7. Write and test the program.
8. Correct mistakes and improve the solution.

**Example:** A program must calculate the total price of three products.

- Problem: Find the total cost.
- Inputs: Price of product 1, product 2, and product 3.
- Process: Add the three prices.
- Output: Display the total price.

**Note:** Do not start writing code immediately. First make sure you understand the problem and the expected output.

## 63. Why is Logical Thinking Important?

**Logical thinking** means using facts, rules, and clear reasoning to reach a conclusion or make a decision.

A computer follows the instructions provided by a programmer. It does not automatically understand what the programmer intended. Therefore, the instructions must be organised correctly.

Logical thinking helps programmers to:

- Arrange instructions in the correct order.
- Make decisions using conditions.
- Identify missing or conflicting steps.
- Predict what a program should do.
- Find the reason for incorrect results.
- Avoid unnecessary instructions.
- Create solutions that are easier to test and maintain.

**Example:** Consider a program that checks whether a person can vote.

- If the person's age is 18 or above, display “Eligible to vote”.
- Otherwise, display “Not eligible to vote”.

The programmer must understand the condition and both possible outcomes.

**Note:** Good programming is not only about knowing programming-language syntax. It also requires the ability to think clearly and solve problems logically.

## 64. Introduction to Computational Logic

**Computational logic** is the use of logical rules and conditions to control how a computer program behaves.

Programs often make decisions by checking whether a condition is true or false. The result of that check determines which instruction should run next.

Common logical concepts include:

- **True:** A condition is satisfied.
- **False:** A condition is not satisfied.
- **AND:** True only when all connected conditions are true.
- **OR:** True when at least one connected condition is true.
- **NOT:** Reverses a logical value.

**Example:** A student can access an examination result if the student is logged in AND has a valid student account.

Both conditions must be true.

```python
is_logged_in = True
has_valid_account = True

if is_logged_in and has_valid_account:
    print("Access granted")
else:
    print("Access denied")
```

**Note:** Logical conditions are commonly used in `if`, `elif`, and `else` statements, loops, authentication, validation, and access-control systems.

## 65. Breaking Problems into Smaller Tasks

Breaking a large problem into smaller tasks is called **decomposition**.

A large problem can feel difficult when viewed as one big activity. Dividing it into smaller tasks makes each part easier to understand, develop, and test.

**Example:** Consider building a student management system.

The main problem can be divided into:

1. Student registration.
2. Student login.
3. Add student details.
4. View student details.
5. Update student details.
6. Delete student details.
7. Search for a student.
8. Generate student reports.

Each task can then be divided further. For example, student registration may include collecting a name, email address, phone number, and course.

**Benefits:**
- Makes large tasks manageable.
- Helps identify what needs to be developed.
- Makes testing easier.
- Allows different tasks to be developed separately.
- Makes errors easier to locate.

**Note:** Solve and test smaller parts one at a time. After the individual parts work correctly, combine them into the complete solution.

## 66. Problem Analysis

**Problem analysis** is the process of studying a problem carefully before designing or writing a solution.

The aim is to understand what is required, what information is available, what restrictions exist, and what result is expected.

A programmer can analyse a problem by asking:

- What exactly is the problem?
- Why does it need to be solved?
- Who will use the solution?
- What information is available?
- What information is required?
- What result should be produced?
- Are there any rules or limitations?
- What unusual situations should be considered?

**Example:** A shop wants a program to calculate discounts.

Before coding, identify:
- Whether the discount is a percentage or fixed amount.
- Whether the discount applies to every product.
- Whether a minimum purchase amount is required.
- Whether the final price can be zero.
- How the final amount should be displayed.

**Note:** A clear analysis reduces misunderstandings and prevents programmers from building a solution that does not meet the actual requirement.

## 67. Identifying Inputs and Outputs

Every basic program receives information, processes it, and produces a result.

- **Input:** The data supplied to a program.
- **Process:** The operations performed on the data.
- **Output:** The result produced by the program.

This is commonly represented as the **Input–Process–Output (IPO) model**.

**Example:** Calculate the area of a rectangle.

| Stage | Description |
|---|---|
| Input | Length and width |
| Process | Multiply length by width |
| Output | Area of the rectangle |

Python example:

```python
length = 10
width = 5

area = length * width

print("Area:", area)
```

Output:

```text
Area: 50
```

**Another example:** For a login program:
- Inputs: Username and password.
- Process: Check the supplied details against the authentication rules.
- Output: Access granted or access denied.

**Note:** Identifying inputs and outputs early helps you decide which data your program needs and what the program must produce.

## 68. Understanding Requirements

**Requirements** describe what a system or program must do and the conditions it must satisfy.

A requirement explains the expected behaviour of the software from the user's or organisation's point of view.

Two common categories are:

### 1. Functional Requirements

Functional requirements describe the features or actions a system must provide.

Examples:
- A user can create an account.
- A student can view marks.
- An administrator can add employee records.
- A customer can place an order.

### 2. Non-Functional Requirements

Non-functional requirements describe the quality or operating expectations of a system.

Examples:
- The application should respond quickly.
- User information must be protected.
- The application should be easy to use.
- The system should support the expected number of users.

**Example:** For an online shopping application:

| Requirement type | Example |
|---|---|
| Functional | Customers can add products to a cart. |
| Functional | Customers can place orders. |
| Non-functional | Payment information must be handled securely. |
| Non-functional | Product pages should load within an acceptable time. |

**Note:** Requirements should be clear, specific, and testable. If a requirement is unclear, ask for clarification before implementing it.

## 69. Step-by-Step Problem-Solving

A step-by-step approach helps programmers solve problems in an organised and repeatable way.

A practical process is:

1. **Define the problem:** Write down what needs to be solved.
2. **Understand the goal:** Identify the expected result.
3. **Gather information:** Find the data and rules needed.
4. **Identify inputs and outputs:** Decide what enters the program and what it should produce.
5. **Break down the task:** Divide the problem into smaller parts.
6. **Plan the logic:** Decide the order of operations and decisions.
7. **Represent the solution:** Use an algorithm, pseudocode, or flowchart.
8. **Write the code:** Convert the planned logic into a programming language.
9. **Test the program:** Check normal, boundary, and unusual cases.
10. **Debug and improve:** Correct mistakes and make the solution clearer.

**Example:** To determine whether a number is even or odd:

- Read a number.
- Divide it by 2 and check the remainder.
- If the remainder is 0, display “Even”.
- Otherwise, display “Odd”.

**Note:** This process is not always strictly linear. Testing may reveal a missing requirement, so you may need to return to the analysis or design stage.

## 70. Introduction to Algorithms

An **algorithm** is a finite, ordered set of clear instructions used to solve a problem or complete a task.

Algorithms describe the logic of a solution without requiring a specific programming language.

**Example:** Algorithm to add two numbers:

1. Start.
2. Read the first number.
3. Read the second number.
4. Add the two numbers.
5. Display the result.
6. Stop.

The same algorithm can be implemented in Python, Java, C, JavaScript, or another suitable language.

**Where are algorithms used?**
- Searching for information.
- Sorting data.
- Calculating totals.
- Finding the shortest route.
- Processing payments.
- Recommending products or content.

**Note:** An algorithm explains how to solve a problem. A program is an implementation of instructions in a programming language.

## 71. Characteristics of an Algorithm

A good algorithm should have the following characteristics:

1. **Input:** It may accept zero or more clearly defined inputs.
2. **Output:** It should produce at least one result.
3. **Definiteness:** Every instruction should be clear and unambiguous.
4. **Finiteness:** It should finish after a finite number of steps.
5. **Effectiveness:** Each step should be simple enough to perform.
6. **Correctness:** It should produce the expected result for valid inputs.
7. **Generality:** It should solve the intended category of problems, not only one accidental example.

**Example:** An algorithm that adds two numbers should work for different valid pairs of numbers, not just for 5 and 10.

**Note:** An algorithm can be clear and still be inefficient. When comparing solutions, programmers also consider time, memory, and scalability.

## 72. Writing Algorithms Using Simple English

An algorithm can be written using ordinary language before it is converted into pseudocode or program code.

This is sometimes called an **informal algorithm** or a step-by-step description.

**Example: Find the largest of two numbers**

1. Start.
2. Ask the user to enter the first number.
3. Ask the user to enter the second number.
4. Compare the two numbers.
5. If the first number is greater, display the first number.
6. Otherwise, display the second number.
7. Stop.

**Example: Calculate a student's average**

1. Start.
2. Read the marks for three subjects.
3. Add the three marks.
4. Divide the total by three.
5. Display the average.
6. Stop.

**Guidelines for writing clear algorithms:**
- Use simple and direct sentences.
- Write steps in the correct order.
- Give each step one clear purpose.
- Include all required decisions.
- Avoid instructions with multiple possible meanings.
- Make sure the process can finish.

**Note:** Simple-English algorithms are useful for discussing a solution with beginners, teammates, or people who do not know a programming language.

## 73. Introduction to Pseudocode

**Pseudocode** is an informal, language-independent way of describing the logic of a program using structured, programming-like statements.

It is not usually executed directly by a computer. Instead, it helps programmers plan a solution before writing actual code.

Common pseudocode words include:

- `START`
- `INPUT` or `READ`
- `OUTPUT` or `DISPLAY`
- `SET`
- `IF`
- `ELSE`
- `WHILE`
- `FOR`
- `STOP`

**Example: Check whether a number is even or odd**

```text
START
    INPUT number

    IF number MOD 2 = 0 THEN
        DISPLAY "Even"
    ELSE
        DISPLAY "Odd"
    END IF
STOP
```

**Python implementation:**

```python
number = int(input("Enter a number: "))

if number % 2 == 0:
    print("Even")
else:
    print("Odd")
```

**Benefits of pseudocode:**
- Easy to read.
- Does not depend on one programming language.
- Helps organise program logic.
- Makes it easier to discuss a solution.
- Helps identify missing steps before coding.

**Note:** Pseudocode has no single universal syntax. The important thing is that the logic is consistent, clear, and understandable.

## 74. Introduction to Flowcharts

A **flowchart** is a visual representation of a process or algorithm. It uses standard symbols connected by arrows to show the order in which steps are performed.

Flowcharts help programmers understand the structure of a solution, including actions, decisions, and the direction of control.

**Example: Flowchart logic for checking an even or odd number**

```text
       (Start)
          |
    / Input number /
          |
   < Is number % 2
        = 0? >
       /     \
     Yes      No
      |        |
 [Display   [Display
  "Even"]    "Odd"]
       \     /
        (Stop)
```

**Why are flowcharts useful?**
- Show the process visually.
- Make the sequence of steps easier to follow.
- Help explain a solution to others.
- Highlight missing steps or unclear decisions.
- Support program planning and documentation.

**Note:** A flowchart represents the logic of a solution. It does not replace testing or guarantee that the final program is correct.

## 75. Flowchart Symbols and Their Uses

Flowcharts use standard shapes to represent different types of steps.

| Symbol name | Common shape | Purpose |
|---|---|---|
| Terminator | Oval | Shows the start or end of a process. |
| Process | Rectangle | Represents an action or calculation. |
| Input/Output | Parallelogram | Represents reading input or displaying output. |
| Decision | Diamond | Represents a condition with branches, such as Yes/No or True/False. |
| Flow line | Arrow | Shows the direction of the process. |
| Connector | Small circle | Connects flowchart sections, often to avoid crossing lines. |
| Predefined process | Rectangle with double vertical edges | Represents a named process or subroutine defined elsewhere. |

**Example of how symbols work together:**

- Oval: Start.
- Parallelogram: Read two numbers.
- Rectangle: Calculate their sum.
- Parallelogram: Display the sum.
- Oval: Stop.

**Important guidelines:**
- Use arrows to show the direction of flow.
- Label decision branches clearly.
- Keep the chart neat and readable.
- Avoid unnecessary line crossings.
- Make sure every path has a clear direction and endpoint where appropriate.

**Note:** The shape communicates the role of a step. For example, use a diamond for a decision, not for an ordinary calculation.

## 76. Decision-Making in Problem-Solving

**Decision-making** is the process of selecting an action based on a condition or set of conditions.

In programming, decisions are commonly implemented using conditional statements such as `if`, `elif`, and `else`.

**Example: Check whether a person is eligible to vote**

```python
age = int(input("Enter your age: "))

if age >= 18:
    print("Eligible to vote")
else:
    print("Not eligible to vote")
```

The program checks the condition `age >= 18`:
- If it is true, the first block runs.
- If it is false, the `else` block runs.

**Multiple decisions:** A program can check several conditions using `if`, `elif`, and `else`.

```python
marks = int(input("Enter marks: "))

if marks >= 90:
    print("Grade A")
elif marks >= 75:
    print("Grade B")
elif marks >= 50:
    print("Grade C")
else:
    print("Needs improvement")
```

**Note:** Conditions should cover the expected cases and be arranged carefully. Test values at the boundaries, such as 49, 50, 74, 75, and 90 in the grading example.

## 77. Pattern Recognition

**Pattern recognition** means identifying similarities, repeated steps, or common features in problems or data.

When programmers recognise a pattern, they may be able to reuse an existing solution instead of designing everything from the beginning.

**Examples:**
- A login form and a registration form both validate user-entered information.
- Monthly sales reports repeat similar calculations for different months.
- A loop repeats the same operation for each item in a list.
- Many applications use a similar process to check whether required fields are empty.

**Programming example:**

```python
numbers = [10, 20, 30, 40]
total = 0

for number in numbers:
    total = total + number

print("Total:", total)
```

The same addition operation is repeated for each number. A loop handles the repeated pattern.

**Benefits:**
- Reduces repeated work.
- Helps identify reusable logic.
- Makes solutions more consistent.
- Supports the use of functions and loops.

**Note:** Not every problem that looks similar has exactly the same requirements. Check the details before reusing a solution.

## 78. Decomposition and Abstraction

**Decomposition** and **abstraction** are two important computational-thinking techniques.

### Decomposition

Decomposition means dividing a complex problem into smaller, more manageable parts.

**Example:** An online shopping application can be divided into:
- User accounts.
- Product catalogue.
- Shopping cart.
- Payment processing.
- Order management.
- Delivery tracking.

### Abstraction

Abstraction means focusing on the information that is important for the current task while leaving out details that are not needed.

**Example:** When calculating the total price of an order, the program may need product prices and quantities. The colour of the shopping cart button is not relevant to that calculation.

### Difference between Decomposition and Abstraction

| Decomposition | Abstraction |
|---|---|
| Divides a problem into smaller parts. | Hides or ignores unnecessary details. |
| Focuses on the structure of a problem. | Focuses on the relevant information. |
| Helps organise development tasks. | Helps reduce complexity. |
| Example: Divide a banking system into account, transfer, and statement features. | Example: Show an account balance without displaying internal database details. |

**Note:** Decomposition helps you decide what parts a solution contains. Abstraction helps you decide which details matter when working on each part.

## 79. Introduction to Debugging Logic

**Debugging** is the process of finding, understanding, and correcting errors in a program.

A program may run without crashing and still produce an incorrect result. This can happen because the logic is wrong.

Common categories of programming errors include:

1. **Syntax errors:** The code breaks the rules of the programming language.
2. **Runtime errors:** An error occurs while the program is running.
3. **Logical errors:** The program runs, but its result or behaviour is incorrect.

**Example of a logical error:**

```python
length = 10
width = 5

area = length + width  # Incorrect logic
print(area)
```

The program runs, but the area of a rectangle should be calculated by multiplying length by width.

**Correct version:**

```python
length = 10
width = 5

area = length * width
print(area)
```

**A simple debugging process:**
1. Reproduce the problem.
2. Identify the expected result.
3. Observe the actual result.
4. Check the relevant instructions and conditions.
5. Test the logic with small examples.
6. Correct the error.
7. Run the tests again.

**Useful debugging techniques:**
- Read error messages carefully.
- Print intermediate values.
- Use a debugger and breakpoints.
- Test normal and boundary values.
- Check conditions and calculation order.
- Change one thing at a time where practical.

**Note:** Debugging is a normal part of software development. Finding an error is an opportunity to understand the program more deeply.

## 80. Real-World Problem-Solving Examples

Problem-solving and logical thinking are used in many everyday and professional situations.

### Example 1: ATM Cash Withdrawal

**Problem:** A customer wants to withdraw money from an ATM.

- Inputs: Account details, PIN, and withdrawal amount.
- Checks: Is the PIN valid? Is the account active? Is the balance sufficient? Is the requested amount allowed?
- Process: Verify the request and update the account balance if the withdrawal is approved.
- Output: Dispense cash or display an appropriate message.

**Note:** A real banking system must also handle security, transaction records, network failures, and other safeguards.

### Example 2: Student Grade Calculator

**Problem:** Calculate a student's grade based on marks.

- Input: Student marks.
- Process: Compare marks against the grading rules.
- Output: Display the corresponding grade.

**Note:** The grading rules must be confirmed before the program is written. Different institutions may use different grade boundaries.

### Example 3: Online Shopping Cart

**Problem:** Calculate the amount a customer must pay.

- Inputs: Product prices and quantities.
- Process: Calculate each line total, add the line totals, and apply eligible discounts or charges.
- Output: Display the order total.

**Note:** The program should also consider cases such as an empty cart, invalid quantities, unavailable products, and failed payments.

### Example 4: Traffic Signal System

**Problem:** Control traffic lights in a planned sequence.

- Input: Timer values and, in some systems, sensor information.
- Process: Follow the traffic-control rules and change signal states safely.
- Output: Red, yellow, or green signals.

**Note:** Traffic-control systems are safety-critical. Their real-world design requires strict rules, reliable hardware, and extensive testing.

### Example 5: Employee Attendance System

**Problem:** Record employee attendance.

- Inputs: Employee ID, date, and check-in/check-out time.
- Process: Validate the employee, record the event, and calculate attendance information according to company rules.
- Output: Attendance status or report.

**Note:** A reliable attendance system must handle duplicate entries, missing check-outs, incorrect times, permissions, and privacy.

### Example 6: Password Validation

**Problem:** Check whether a password meets defined rules.

- Input: Password entered by the user.
- Process: Check required length and any other agreed password rules.
- Output: Display whether the password meets the requirements.

**Note:** A real authentication system must not store plain-text passwords. It should use appropriate password hashing and security practices.
