# **1.9 Introduction to Programming Errors**

Programming errors are mistakes or problems that occur while writing, compiling, executing, or maintaining a computer program. These errors may prevent a program from running, produce incorrect results, or cause unexpected behavior.

Understanding programming errors is an important part of learning programming because no programmer writes perfect code every time. Even experienced developers make mistakes. The ability to identify, understand, debug, and correct errors is an essential programming skill.

---

## **129. What is a Programming Error?**

### **Definition**

A programming error is a mistake in a computer program that causes the program to behave incorrectly, produce unexpected output, or fail to execute.

A programming error can occur while writing code, designing program logic, compiling source code, or executing a program.

### **Why Do We Need to Understand Programming Errors?**

- To identify problems in a program.
- To understand why a program is not working correctly.
- To improve code quality.
- To prevent incorrect results.
- To develop problem-solving skills.
- To build reliable and maintainable software.

### **Example**

```python
num1 = 10
num2 = 0

result = num1 / num2

print(result)
```

**Output:**

```text
ZeroDivisionError: division by zero
```

**Explanation:**

- The program attempts to divide `10` by `0`.
- Division by zero is not allowed in Python.
- Python raises a runtime error.
- The program stops before printing the result.

### **Corrected Code**

```python
num1 = 10
num2 = 0

if num2 != 0:
    result = num1 / num2
    print(result)
else:
    print("Cannot divide by zero")
```

**Output:**

```text
Cannot divide by zero
```

**Note:**
A programming error does not always mean that the code contains incorrect syntax. A program can execute successfully and still produce an incorrect result because of a mistake in its logic.

## **130. What is a Bug?**

### **Definition**

A bug is a defect or flaw in a software program that causes it to produce incorrect results, behave unexpectedly, or fail to perform its intended functionality.

The term *bug* is commonly used in software development to describe problems discovered during development, testing, or after software deployment.

### **Why Are Bugs Important to Understand?**

- Bugs affect software functionality.
- Bugs can create security vulnerabilities.
- Bugs can cause application crashes.
- Bugs can result in incorrect data.
- Bugs can negatively affect user experience.
- Identifying and fixing bugs improves software quality.

### **Real-World Examples**

| Application | Example of a Bug |
|---|---|
| Banking application | Incorrect account balance |
| E-commerce website | Incorrect product price |
| Hospital management system | Incorrect patient information |
| Attendance application | Incorrect attendance calculation |
| Social media application | Messages not appearing |
| Education platform | Incorrect examination results |

### **Example**

Suppose a shopping application calculates the total price of two products.

**Incorrect Code:**

```python
price1 = 500
price2 = 300

total = price1 - price2

print("Total Price:", total)
```

**Output:**

```text
Total Price: 200
```

**Expected Output:**

```text
Total Price: 800
```

**Explanation:**

The programmer accidentally used the subtraction operator (`-`) instead of the addition operator (`+`).

This is a logical bug because the program executes successfully but produces an incorrect result.

### **Corrected Code**

```python
price1 = 500
price2 = 300

total = price1 + price2

print("Total Price:", total)
```

**Note:**
A bug is a defect in software behavior. A programming error is a mistake that can introduce a bug. The terms are closely related and are often used interchangeably in everyday development discussions.

## **131. Why Do Programming Errors Occur?**

Programming errors occur for several reasons. They may happen because of incorrect syntax, improper logic, incorrect data, misunderstanding of requirements, or unexpected conditions during program execution.

### **Common Reasons for Programming Errors**

1. **Incorrect Syntax:** Writing code that does not follow the programming language's grammar rules.

2. **Incorrect Logic:** Using the wrong conditions, calculations, or algorithms.

3. **Lack of Programming Knowledge:** Not understanding programming concepts properly.

4. **Incorrect Variable Usage:** Using an undefined variable or assigning an incorrect value.

5. **Incorrect Data Types:** Performing operations with incompatible data types.

6. **Invalid User Input:** Receiving unexpected or invalid information from users.

7. **Incorrect Function Usage:** Passing incorrect arguments to functions or calling functions incorrectly.

8. **Memory-Related Problems:** Using memory incorrectly or accessing invalid memory locations in languages where this is possible.

9. **Poor Testing:** Not testing programs with different inputs and conditions.

10. **Requirement Misunderstanding:** Implementing functionality differently from what the user or client requested.

11. **Integration Problems:** Different software components may not communicate correctly.

12. **External Dependency Problems:** Errors may occur because of unavailable APIs, databases, libraries, or network connections.

### **Example 1: Incorrect Variable Name**

```python
name = "Maheswari"

print(nam)
```

**Output:**

```text
NameError: name 'nam' is not defined
```

**Explanation:**

The variable is declared as `name`, but the programmer uses `nam` while printing it.

### **Corrected Code**

```python
name = "Maheswari"

print(name)
```

### **Example 2: Incorrect Data Type**

```python
age = 25

print("Age: " + age)
```

**Output:**

```text
TypeError: can only concatenate str (not "int") to str
```

**Corrected Code**

```python
age = 25

print("Age:", age)
```

**Note:**
Most programming errors can be reduced through proper planning, understanding programming fundamentals, writing readable code, testing different scenarios, and reviewing code regularly.

## **132. Types of Programming Errors**

Programming errors can be classified into different categories based on when they occur and how they affect a program.

### **Major Types of Programming Errors**

| Error Type | Meaning | Example |
|---|---|---|
| Syntax Error | Violation of programming language syntax rules | Missing colon |
| Runtime Error | Error that occurs during program execution | Division by zero |
| Logical Error | Incorrect program logic | Using subtraction instead of addition |
| Semantic Error | Code has an invalid or unintended meaning | Using an inappropriate operation |
| Compilation Error | Error detected during compilation | Undeclared variable in C |

### **Classification Based on Program Execution**

1. **Before Execution**
   - Syntax errors
   - Compilation errors
   - Some static analysis errors

2. **During Execution**
   - Runtime errors
   - Exceptions
   - Memory access errors

3. **After Execution or During Testing**
   - Logical errors
   - Incorrect output
   - Unexpected application behavior

### **Example**

```python
# Syntax error
if 10 > 5
    print("Greater")
```

```python
# Runtime error
print(10 / 0)
```

```python
# Logical error
a = 10
b = 20

result = a - b

print(result)
```

**Note:**
Different programming languages detect errors differently. For example, Python generally detects syntax errors before executing the affected program, while compiled languages such as C and C++ typically report many syntax and type-related problems during compilation.

## **133. Syntax Errors**

### **Definition**

A syntax error occurs when the programmer violates the grammar or structural rules of a programming language.

Every programming language has specific rules for writing statements, declaring variables, defining functions, and using operators.

If these rules are not followed, the interpreter or compiler reports a syntax error.

### **Common Causes of Syntax Errors**

- Missing brackets.
- Missing quotation marks.
- Missing colons.
- Incorrect indentation in Python.
- Misspelled keywords.
- Incorrect statement structure.
- Missing parentheses.
- Incorrect use of operators.

### **Example 1: Missing Colon**

**Incorrect Code:**

```python
if 10 > 5
    print("10 is greater than 5")
```

**Output:**

```text
SyntaxError: expected ':'
```

**Corrected Code:**

```python
if 10 > 5:
    print("10 is greater than 5")
```

**Output:**

```text
10 is greater than 5
```

### **Example 2: Missing Closing Parenthesis**

**Incorrect Code:**

```python
print("Hello World"
```

**Corrected Code:**

```python
print("Hello World")
```

### **Example 3: Incorrect String Quotation**

**Incorrect Code:**

```python
name = "Maheswari
```

**Corrected Code:**

```python
name = "Maheswari"
```

### **How to Identify Syntax Errors**

1. Read the error message carefully.
2. Check the line number mentioned in the error.
3. Verify brackets and quotation marks.
4. Check indentation.
5. Verify the spelling of keywords.
6. Correct the syntax and execute the program again.

**Note:**
Syntax errors usually prevent the affected program or module from executing. Correct syntax is the first requirement for writing a valid program.

## **134. Runtime Errors**

### **Definition**

A runtime error is an error that occurs while a program is executing.

A program may have valid syntax and successfully begin execution, but an unexpected situation can cause it to stop or behave incorrectly.

### **Common Causes of Runtime Errors**

- Dividing a number by zero.
- Accessing an invalid list index.
- Using an undefined variable.
- Opening a file that does not exist.
- Converting incompatible data types.
- Accessing unavailable resources.
- Network connection failures.
- Database connection failures.

### **Example 1: Division by Zero**

```python
a = 100
b = 0

result = a / b

print(result)
```

**Output:**

```text
ZeroDivisionError: division by zero
```

### **Corrected Code**

```python
a = 100
b = 0

if b != 0:
    print(a / b)
else:
    print("Division by zero is not allowed")
```

### **Example 2: Invalid List Index**

```python
numbers = [10, 20, 30]

print(numbers[5])
```

**Output:**

```text
IndexError: list index out of range
```

### **Corrected Code**

```python
numbers = [10, 20, 30]

print(numbers[2])
```

**Output:**

```text
30
```

### **Example 3: Handling Runtime Errors**

Python provides `try` and `except` blocks to handle many runtime exceptions.

```python
try:
    number = int(input("Enter a number: "))
    result = 100 / number

    print("Result:", result)

except ZeroDivisionError:
    print("Cannot divide by zero")

except ValueError:
    print("Please enter a valid integer")
```

**Note:**
Runtime errors can often be handled using exception handling, input validation, and proper resource management. However, exception handling should not be used to hide programming mistakes.

## **135. Logical Errors**

### **Definition**

A logical error occurs when a program executes without producing a syntax or runtime error but gives an incorrect result because the programmer has implemented the wrong logic.

Logical errors are sometimes difficult to identify because the program may appear to work correctly.

### **Common Causes of Logical Errors**

- Using incorrect mathematical operators.
- Writing incorrect conditions.
- Applying the wrong algorithm.
- Using incorrect comparison operators.
- Incorrect loop conditions.
- Incorrect variable updates.
- Misunderstanding the problem requirements.

### **Example 1: Incorrect Addition**

**Problem:** Calculate the total marks of two subjects.

**Incorrect Code:**

```python
maths = 80
science = 90

total = maths - science

print("Total Marks:", total)
```

**Output:**

```text
Total Marks: -10
```

**Expected Output:**

```text
Total Marks: 170
```

**Corrected Code:**

```python
maths = 80
science = 90

total = maths + science

print("Total Marks:", total)
```

### **Example 2: Incorrect Age Condition**

**Incorrect Code:**

```python
age = 20

if age > 18:
    print("Not Eligible")
else:
    print("Eligible")
```

**Explanation:**

The condition is opposite to the intended requirement.

**Corrected Code:**

```python
age = 20

if age >= 18:
    print("Eligible")
else:
    print("Not Eligible")
```

**Output:**

```text
Eligible
```

### **How to Identify Logical Errors**

1. Understand the expected output.
2. Run the program with sample inputs.
3. Compare actual output with expected output.
4. Check calculations and conditions.
5. Test boundary values.
6. Trace the program step by step.
7. Correct the incorrect logic.

**Note:**
Logical errors are not always detected automatically by a compiler or interpreter. Developers must verify program behavior through testing, debugging, and reviewing the requirements.

## **136. Semantic Errors**

### **Definition**

A semantic error occurs when a statement is syntactically valid but its meaning is incorrect, invalid, or different from what the programmer intended.

In simple terms, the program may follow the language's grammar rules, but the operation or meaning does not correctly represent the intended task.

Semantic errors can be detected during compilation, static analysis, testing, or execution, depending on the programming language and the type of mistake.

### **Common Causes of Semantic Errors**

- Using an inappropriate operation.
- Assigning an incorrect meaning to a variable.
- Passing an argument with an incorrect meaning.
- Using a function for the wrong purpose.
- Applying an incorrect condition.
- Misunderstanding the problem requirements.

### **Example 1: Incorrect Operation**

Suppose a programmer wants to calculate the area of a rectangle.

**Incorrect Code:**

```python
length = 10
width = 5

area = length + width

print("Area:", area)
```

**Output:**

```text
Area: 15
```

**Explanation:**

The code is syntactically valid, but addition does not calculate the area of a rectangle.

**Corrected Code:**

```python
length = 10
width = 5

area = length * width

print("Area:", area)
```

**Output:**

```text
Area: 50
```

### **Example 2: Incorrect Function Meaning**

```python
def calculate_square(number):
    return number + number

print(calculate_square(5))
```

**Output:**

```text
10
```

**Expected Output:**

```text
25
```

**Corrected Code:**

```python
def calculate_square(number):
    return number * number

print(calculate_square(5))
```

**Note:**
Semantic errors and logical errors are closely related. In introductory programming, an incorrect operation or condition is often described as a logical error. Semantic error is a broader term whose exact meaning can vary by programming language and context.

## **137. Compilation Errors**

### **Definition**

A compilation error is an error detected by a compiler while translating source code into machine code or another target representation.

A compiler checks whether the source code follows the language's rules and whether it can be translated successfully.

If certain errors are detected, the compiler reports them and may prevent the program from being generated.

### **Common Causes of Compilation Errors**

- Missing semicolons in languages that require them.
- Undeclared variables.
- Incorrect data types.
- Missing brackets.
- Invalid function declarations.
- Incorrect syntax.
- Incompatible operations.
- Missing required libraries or dependencies.

### **Example Using C**

**Incorrect Code:**

```c
#include <stdio.h>

int main() {
    int number = 10

    printf("%d", number);

    return 0;
}
```

**Problem:**

A semicolon is missing after the variable declaration.

**Corrected Code:**

```c
#include <stdio.h>

int main() {
    int number = 10;

    printf("%d", number);

    return 0;
}
```

**Output:**

```text
10
```

### **How Compilation Works**

1. The programmer writes source code.
2. The compiler reads the source code.
3. The compiler checks the code for errors.
4. If compilation succeeds, it generates the required output.
5. The generated program can be executed.

### **Compilation vs Runtime Errors**

| Compilation Error | Runtime Error |
|---|---|
| Detected during compilation | Occurs during execution |
| May prevent program generation | Program has started executing |
| Example: Missing semicolon in C | Example: Division by zero |
| Reported by the compiler | Reported during program execution |

**Note:**
Python is generally an interpreted language, so beginners usually encounter syntax and runtime errors rather than a separate compilation step like the traditional C compilation workflow. Python does perform internal compilation to bytecode, but this is usually handled automatically.

## **138. Introduction to Debugging**

### **Definition**

Debugging is the process of identifying, analyzing, and correcting errors or defects in a computer program.

A programmer uses debugging techniques and tools to understand why a program is not behaving as expected.

The main goal of debugging is to find the root cause of a problem and fix it without introducing additional problems.

### **Why Is Debugging Important?**

- To identify programming errors.
- To understand program execution.
- To correct incorrect output.
- To improve application performance and reliability.
- To prevent repeated problems.
- To improve code quality.
- To develop problem-solving skills.

### **Common Debugging Techniques**

1. **Print Debugging:** Display variable values using print statements.

2. **Step-by-Step Debugging:** Execute the program one statement at a time.

3. **Breakpoint Debugging:** Pause execution at a specific line.

4. **Variable Inspection:** Check the current values of variables.

5. **Call Stack Inspection:** Understand which functions called one another.

6. **Logging:** Record application events and errors.

7. **Code Review:** Ask another developer to review the code.

8. **Testing:** Run test cases to identify incorrect behavior.

### **Example: Debugging with Print Statements**

**Problem:** Find the total of two numbers.

```python
a = 10
b = 20

total = a - b

print("Total:", total)
```

**Output:**

```text
Total: -10
```

The expected output is `30`.

### **Debugging the Program**

```python
a = 10
b = 20

print("Value of a:", a)
print("Value of b:", b)

total = a - b

print("Calculated Total:", total)
```

**Output:**

```text
Value of a: 10
Value of b: 20
Calculated Total: -10
```

After checking the calculation, the programmer identifies that the subtraction operator is incorrect.

### **Corrected Program**

```python
a = 10
b = 20

total = a + b

print("Total:", total)
```

**Output:**

```text
Total: 30
```

### **Popular Debugging Tools**

| Tool | Purpose |
|---|---|
| Python Debugger (`pdb`) | Debug Python programs |
| VS Code Debugger | Debug applications using breakpoints |
| PyCharm Debugger | Debug Python applications |
| Chrome DevTools | Debug JavaScript and web applications |
| Browser Console | Inspect errors and application messages |
| GDB | Debug C and C++ programs |

**Note:**
Debugging is not simply fixing an error. It involves understanding the problem, identifying its root cause, applying a suitable solution, and verifying that the program works correctly afterward.

## **139. Error Detection and Correction**

### **Definition**

Error detection is the process of identifying errors in a program, while error correction is the process of fixing those errors.

Programmers use different techniques to detect and correct errors during development and testing.

### **Error Detection Methods**

1. **Reading Error Messages:** Understand the message provided by the compiler or interpreter.

2. **Code Inspection:** Read the source code to identify mistakes.

3. **Testing:** Execute the program using different inputs.

4. **Debugging:** Use debugging tools to trace program execution.

5. **Logging:** Record errors and application events.

6. **Static Code Analysis:** Analyze source code without executing it.

7. **Code Review:** Ask other developers to inspect the code.

8. **Automated Testing:** Run predefined test cases automatically.

### **Error Correction Methods**

1. Identify the exact problem.
2. Understand why the error occurred.
3. Locate the affected statement or function.
4. Correct the code.
5. Execute the program again.
6. Compare actual output with expected output.
7. Run related tests to ensure the fix has not introduced another problem.

### **Example: Error Detection and Correction**

**Problem:** Calculate the average of three numbers.

**Incorrect Code:**

```python
num1 = 10
num2 = 20
num3 = 30

average = num1 + num2 + num3 / 3

print("Average:", average)
```

**Output:**

```text
Average: 40.0
```

**Expected Output:**

```text
Average: 20.0
```

**Explanation:**

The division operator is evaluated before addition because of operator precedence. Therefore, only `num3` is divided by `3`.

### **Corrected Code**

```python
num1 = 10
num2 = 20
num3 = 30

average = (num1 + num2 + num3) / 3

print("Average:", average)
```

**Output:**

```text
Average: 20.0
```

### **Error Detection and Correction Workflow**

```text
Write the Program
       |
       v
Execute the Program
       |
       v
Check the Output
       |
       v
Is the Output Correct?
       |
   +---+---+
   |       |
  Yes      No
   |       |
   v       v
Continue  Identify the Error
           |
           v
      Find the Root Cause
           |
           v
       Correct the Code
           |
           v
       Run the Program
           |
           v
      Test the Output Again
```

### **Example from Real-World Software Development**

Suppose an employee attendance application calculates the number of working days incorrectly.

**Detection:**
- HR notices that the monthly attendance report contains incorrect totals.
- The development team checks the attendance calculation.
- Developers identify that weekly holidays are included incorrectly.

**Correction:**
- Update the attendance calculation logic.
- Test different employee attendance records.
- Verify monthly attendance reports.
- Deploy the corrected version after successful testing.

**Note:**
Fixing an error does not mean the entire application is automatically correct. Developers should perform regression testing to ensure that the correction has not affected existing functionality.

## **140. Best Practices for Writing Error-Free Code**

### **Definition**

Writing error-free code means following programming standards and development practices that reduce mistakes and improve the reliability, readability, security, and maintainability of software.

It is not always possible to write completely error-free code, but programmers can significantly reduce errors by following good coding practices.

### **Best Practices**

**1. Understand the Problem Before Coding**

- Read the requirements carefully.
- Identify the expected input.
- Identify the expected output.
- Understand the conditions and limitations.
- Plan the solution before writing code.

**Example:**

Before developing a calculator, understand which operations are required: addition, subtraction, multiplication, and division.

**2. Use Meaningful Variable Names**

Choose names that clearly describe the purpose of variables.

**Bad Example:**

```python
x = 500
y = 300
z = x + y
```

**Good Example:**

```python
product_price = 500
delivery_charge = 300

total_amount = product_price + delivery_charge

print(total_amount)
```

**3. Follow Proper Indentation**

Use consistent indentation to make code readable and avoid indentation-related errors.

```python
age = 22

if age >= 18:
    print("Eligible to vote")
else:
    print("Not eligible to vote")
```

**4. Write Small and Reusable Functions**

Divide large programs into smaller functions.

```python
def calculate_total(price1, price2):
    return price1 + price2

total = calculate_total(500, 300)

print("Total:", total)
```

**5. Validate User Input**

Always check whether user input is valid before processing it.

```python
age = int(input("Enter your age: "))

if age >= 0:
    print("Valid age")
else:
    print("Invalid age")
```

For production applications, also handle non-numeric input using exception handling.

**6. Handle Exceptions Properly**

Use exception handling to manage expected errors.

```python
try:
    number = int(input("Enter a number: "))
    print("Number:", number)

except ValueError:
    print("Please enter a valid number")
```

**7. Test Your Program Regularly**

Test the program using:

- Normal inputs.
- Invalid inputs.
- Empty inputs.
- Minimum values.
- Maximum values.
- Boundary conditions.
- Unexpected inputs.

**8. Use Comments Where Necessary**

Comments explain complex logic and help other developers understand the program.

```python
# Calculate the total price of two products

price1 = 500
price2 = 300

total = price1 + price2

print(total)
```

**9. Avoid Repeating Code**

Use functions and reusable components instead of copying the same logic repeatedly.

**10. Review Your Code**

Check the code for:

- Incorrect conditions.
- Unnecessary variables.
- Duplicate logic.
- Incorrect calculations.
- Unhandled exceptions.
- Security issues.

**11. Use Version Control**

Use Git and GitHub to track changes, review code, and recover earlier versions when necessary.

**12. Follow Coding Standards**

Use consistent naming conventions, formatting, indentation, and project structure.

**13. Use Automated Testing**

Write test cases to verify that individual functions and complete application workflows work correctly.

**14. Keep Dependencies Updated Carefully**

Use reliable libraries and review updates before applying them to production applications.

**15. Never Ignore Error Messages**

Read error messages carefully and understand their causes instead of blindly changing code.

### **Example: A Program Following Good Coding Practices**

```python
def calculate_total(price1, price2):
    if price1 < 0 or price2 < 0:
        return None

    return price1 + price2


def main():
    product1_price = 500
    product2_price = 300

    total_amount = calculate_total(
        product1_price,
        product2_price
    )

    if total_amount is not None:
        print("Total Amount:", total_amount)
    else:
        print("Invalid product price")


main()
```

**Output:**

```text
Total Amount: 800
```

**Explanation:**

This program demonstrates:

- Meaningful variable names.
- Reusable functions.
- Input validation at the calculation level.
- Proper indentation.
- Clear program structure.
- Readable code.

**Note:**
No programmer can guarantee that every program will be completely free of errors. The objective is to prevent common mistakes, identify defects early, test thoroughly, and continuously improve code quality.

# **Final Note**

Programming errors are a normal part of software development. Beginners should not feel discouraged when their programs produce errors. Instead, every error should be treated as an opportunity to understand how a programming language works.

A good programmer is not someone who never makes mistakes. A good programmer is someone who can identify problems, understand their root causes, correct them, and prevent similar mistakes in the future.

**Remember:** Write the code, execute it, understand the error, debug it, correct it, and test it again. This process builds strong programming and problem-solving skills.
