# **1.7 Introduction to Software Development**

This chapter explains Software Development from basic to advanced level. It covers software fundamentals, types of software applications, Software Development Life Cycle (SDLC), development methodologies, Agile, Scrum, Version Control, Git and GitHub.

The explanations are designed to help beginners understand concepts, learn practical applications, and explain technical topics confidently.

## **99. What is Software Development?**

### **Definition**
Software Development is the process of designing, creating, programming, testing, deploying, and maintaining software applications to solve real-world problems and fulfil user requirements.

It involves converting an idea or business requirement into a working software product using programming languages, development tools, frameworks, databases, and other technologies.

### **What Does Software Development Include?**

1. Understanding the problem.
2. Gathering user requirements.
3. Planning the software project.
4. Designing the user interface and software architecture.
5. Writing source code using programming languages.
6. Connecting databases and APIs.
7. Testing the software to identify errors.
8. Fixing bugs and improving performance.
9. Deploying the application for users.
10. Maintaining and updating the software.

### **Why is Software Development Important?**

- Automates repetitive tasks.
- Reduces manual work.
- Improves business productivity.
- Helps organizations manage data.
- Provides digital solutions to customers.
- Improves communication and collaboration.
- Supports business growth and scalability.
- Solves complex real-world problems.

### **Real-World Examples**

| Software | Purpose |
|---|---|
| Google Chrome | Browsing websites |
| WhatsApp | Communication |
| Amazon | Online shopping |
| Google Maps | Navigation |
| Microsoft Excel | Data management |
| Banking Applications | Financial transactions |
| Hospital Management Systems | Managing patient records |
| Netflix | Video streaming |

### **Example: Developing an Online Shopping Application**

Suppose a company wants to develop an online shopping application.

1. Understand what customers need.
2. Design product listing and shopping cart pages.
3. Develop the frontend using React.
4. Develop backend APIs using Python or Node.js.
5. Store product and customer information in a database.
6. Integrate payment functionality.
7. Test the application.
8. Deploy the application.
9. Maintain and improve the application.

**Note:** Software Development is not just writing code. It is a complete process that starts with identifying a problem and ends with delivering and maintaining a working software solution.

## **102. What is System Software?**

### **Definition**
System Software is a type of software that manages computer hardware, controls system resources, and provides a platform for running application software.

It acts as an interface between computer hardware and application software.

### **Why is System Software Required?**

- Manages CPU operations.
- Controls memory allocation.
- Manages storage devices.
- Handles input and output operations.
- Controls hardware devices.
- Provides security and access control.
- Allows applications to execute.

### **Types of System Software**

1. Operating Systems
2. Device Drivers
3. Language Translators
4. System Utilities
5. Firmware

### **Examples**

| Type | Examples |
|---|---|
| Operating System | Windows, Linux, macOS |
| Device Drivers | Printer and Graphics Drivers |
| Compiler | GCC |
| Interpreter | Python Interpreter |
| Firmware | BIOS, UEFI |
| System Utilities | Disk Management Tools |

### **How Does System Software Work?**

1. A user switches on the computer.
2. Firmware initializes the hardware.
3. The operating system starts.
4. The operating system manages system resources.
5. Applications request services from the operating system.
6. The operating system communicates with hardware through appropriate system interfaces and drivers.

### **Real-World Example**

When you open Google Chrome:

- The operating system allocates memory.
- The CPU executes program instructions.
- The operating system manages access to storage and network resources.
- Display drivers help render the application on the screen.

**Note:** System Software manages the computer's underlying operations and provides the environment required to run application software.

## **104. What is a Web Application?**

### **Definition**
A Web Application is a software application that users access through a web browser over a network, usually the internet.

Web applications typically consist of frontend, backend, database, and API components.

### **Why are Web Applications Used?**

- Access applications from different devices.
- Avoid installing traditional desktop software.
- Share information online.
- Support multiple users.
- Simplify business operations.
- Provide centralized data management.

### **Main Components of a Web Application**

1. Frontend
2. Backend
3. Database
4. APIs
5. Web Server
6. Hosting Environment
7. Authentication and Authorization

### **Technologies Used**

| Component | Technologies |
|---|---|
| Frontend | HTML, CSS, JavaScript, React |
| Backend | Node.js, Python, Java, PHP |
| Database | MySQL, PostgreSQL, SQLite |
| API | REST API, GraphQL |
| Web Server | Nginx, Apache |
| Deployment | AWS, Azure, Vercel |

### **How Does a Web Application Work?**

1. A user opens a browser.
2. The user enters a website address.
3. The browser sends an HTTP request.
4. The web server receives the request.
5. The backend processes the request.
6. The backend communicates with the database if required.
7. The server sends a response.
8. The browser displays the result.

### **Real-World Examples**

- Gmail – Email services.
- Amazon – Online shopping.
- Google Docs – Online document editing.
- Salesforce – Customer relationship management.
- Netflix – Online entertainment.

### **Example: Employee Management Web Application**

An employee logs into a company website.

The application allows the employee to:

- View their profile.
- Check attendance.
- Apply for leave.
- View salary information.
- Update personal details.

The frontend displays the information, the backend processes requests, and the database stores employee records.

**Note:** Web applications are commonly developed using frontend technologies, backend programming languages, databases, APIs, and cloud hosting platforms.

## **107. What is Embedded Software?**

### **Definition**
Embedded Software is specialized software programmed into electronic devices to control their operations and perform specific functions.

It generally operates within an embedded system that combines hardware and software.

### **Why is Embedded Software Required?**

- To control electronic devices.
- To automate physical operations.
- To process sensor information.
- To control hardware components.
- To perform real-time operations.
- To improve device efficiency.

### **Where is Embedded Software Used?**

1. Washing Machines
2. Smart TVs
3. Cars
4. Medical Equipment
5. Industrial Machines
6. Smart Watches
7. Traffic Control Systems
8. Air Conditioners
9. Digital Cameras
10. IoT Devices

### **Technologies Used**

- C
- C++
- Embedded C
- Assembly Language
- Microcontrollers
- Real-Time Operating Systems (RTOS)
- Arduino
- Raspberry Pi

### **How Does Embedded Software Work?**

1. Sensors collect information.
2. The embedded controller receives the information.
3. The software processes the input.
4. The controller determines the required operation.
5. The hardware performs the operation.

### **Real-World Example: Washing Machine**

1. The user selects a washing mode.
2. The embedded software receives the selection.
3. The software controls water intake.
4. It monitors water levels.
5. It controls the motor.
6. It manages washing and spinning cycles.
7. It stops the machine when the process is complete.

**Note:** Embedded Software connects programming with physical hardware. It is widely used in automotive systems, healthcare equipment, industrial automation, robotics, and IoT.

## **108. What is the Software Development Life Cycle (SDLC)?**

### **Definition**
The Software Development Life Cycle (SDLC) is a structured process used by software development teams to plan, design, develop, test, deploy, and maintain software applications.

It provides a systematic approach to building high-quality software within defined time, budget, and resource constraints.

### **Why is SDLC Required?**

- Provides a structured development process.
- Helps understand project requirements.
- Improves software quality.
- Reduces development risks.
- Helps manage project costs.
- Improves team collaboration.
- Ensures proper testing and documentation.
- Supports timely software delivery.

### **Phases of SDLC**

1. Requirement Gathering and Analysis
2. Planning
3. Software Design
4. Development
5. Testing
6. Deployment
7. Maintenance

### **SDLC Process Flow**

```text
Requirement Gathering
         |
         v
      Planning
         |
         v
   Software Design
         |
         v
     Development
         |
         v
       Testing
         |
         v
      Deployment
         |
         v
     Maintenance
         |
         v
 Continuous Improvement
```

### **Types of SDLC Models**

1. Waterfall Model
2. Agile Model
3. Iterative Model
4. Incremental Model
5. Spiral Model
6. V-Model
7. Prototype Model
8. Big Bang Model

### **Real-World Example**

Consider developing a Hospital Management System.

| SDLC Phase | Activity |
|---|---|
| Requirements | Understand hospital operations |
| Planning | Estimate budget and development time |
| Design | Design patient and doctor modules |
| Development | Build frontend, backend and database |
| Testing | Test appointments and patient records |
| Deployment | Release the system to the hospital |
| Maintenance | Fix bugs and introduce improvements |

**Note:** SDLC is one of the most important concepts in software engineering. Every software developer should understand its phases and how they work together.

## **109. What is Requirement Gathering in Software Development?**

### **Definition**
Requirement Gathering is the process of collecting, understanding, analyzing, and documenting the needs and expectations of users, customers, and stakeholders before developing a software application.

It helps the development team understand what needs to be built and why.

### **Why is Requirement Gathering Important?**

- Understands customer expectations.
- Identifies business problems.
- Defines project scope.
- Prevents misunderstandings.
- Reduces unnecessary development work.
- Helps estimate project cost and time.
- Provides a foundation for software design and testing.

### **Who is Involved in Requirement Gathering?**

1. Clients
2. Customers
3. Business Analysts
4. Project Managers
5. Software Architects
6. Developers
7. QA Engineers
8. End Users

### **Types of Software Requirements**

**1. Functional Requirements**

Describe what the software must do.

Examples:
- User login.
- Employee registration.
- Leave application.
- Attendance tracking.
- Salary calculation.

**2. Non-Functional Requirements**

Describe how the software should perform.

Examples:
- Security.
- Performance.
- Scalability.
- Reliability.
- Availability.
- Usability.

### **Requirement Gathering Techniques**

1. Interviews.
2. Questionnaires.
3. Surveys.
4. Workshops.
5. Brainstorming.
6. Observation.
7. Document Analysis.
8. User Stories.

### **Real-World Example: Employee Management System**

The client requests an employee management application.

The business analyst gathers these requirements:

- Admin can register employees.
- HR can manage employee records.
- Managers can approve leave requests.
- Employees can view their attendance.
- Employees can access their salary information.
- The system must provide secure login.
- Only authorized users can access specific modules.

These requirements are documented and shared with the development team.

### **Important Documents**

- Business Requirement Document (BRD).
- Software Requirement Specification (SRS).
- Functional Requirement Document (FRD).
- User Stories.
- Use Case Diagrams.
- Acceptance Criteria.

**Note:** Requirement Gathering is the foundation of software development. If requirements are misunderstood, the final application may not solve the actual business problem.

## **110. What is Software Planning and Design?**

### **Definition**
Software Planning and Design is the SDLC stage in which the development team determines how the software will be built, which technologies will be used, what resources are required, and how the system will be structured.

Planning focuses on project execution, while design focuses on the technical structure and appearance of the software.

### **Part A: Software Planning**

Software Planning involves:

1. Defining project objectives.
2. Identifying project scope.
3. Estimating development time.
4. Estimating project cost.
5. Allocating team members.
6. Selecting technologies.
7. Identifying risks.
8. Preparing project schedules.
9. Defining milestones.
10. Establishing communication processes.

### **Part B: Software Design**

Software Design involves:

1. Designing system architecture.
2. Designing database structures.
3. Designing user interfaces.
4. Defining application modules.
5. Designing API communication.
6. Defining data flow.
7. Planning security mechanisms.
8. Defining application navigation.

### **Types of Software Design**

**1. High-Level Design (HLD)**

Describes the overall system architecture.

Examples:
- Frontend architecture.
- Backend architecture.
- Database architecture.
- API communication.
- System components.

**2. Low-Level Design (LLD)**

Describes the internal implementation details.

Examples:
- Classes.
- Functions.
- Methods.
- Database fields.
- API request structures.
- Component logic.

### **Technologies and Tools**

| Purpose | Tools |
|---|---|
| UI/UX Design | Figma |
| Diagram Design | Draw.io |
| Project Management | Jira |
| Documentation | Confluence |
| Database Design | MySQL Workbench |
| Architecture Diagrams | Lucidchart |

### **Real-World Example**

For an Employee Management System:

- Planning: Decide budget, timeline, team members and technology stack.
- UI Design: Design login, dashboard and employee pages.
- Architecture Design: Decide frontend, backend and database structure.
- Database Design: Create employee, attendance and leave tables.
- API Design: Define employee registration and attendance endpoints.

**Note:** Proper planning and design reduce technical problems and help developers build maintainable, scalable, and reliable applications.

Software Testing is the process of evaluating a software application to identify defects, verify functionality, validate requirements, and ensure that the application works as expected.

Testing helps determine whether the software meets its functional and non-functional requirements.

### **Why is Software Testing Required?**

- Identifies software defects.
- Prevents unexpected failures.
- Improves application quality.
- Validates business requirements.
- Protects user information.
- Improves application performance.
- Reduces production issues.
- Ensures a better user experience.

### **Types of Software Testing**

- Cypress.

### **Important Testing Levels**

- Stress Testing.

## **113. What is Software Deployment?**

### **Definition**
Software Deployment is the process of releasing and making a software application available in a target environment so that users can access and use it.

Deployment involves preparing application files, configuring servers, setting up databases, managing environment variables, and publishing the application.

### **Why is Software Deployment Required?**

- Makes software available to users.
- Releases new features.
- Provides application updates.
- Supports business operations.
- Enables production usage.
- Helps deliver bug fixes.
- Supports application scaling.

### **Types of Deployment Environments**

**2. Testing Environment**

**3. Staging Environment**

### **Deployment Process**

4. Build the application.
5. Configure the deployment environment.
6. Configure server and database.

## **114. What is Software Maintenance?**

### **Definition**
Software Maintenance is the process of modifying, updating, fixing, and improving software after it has been deployed.

Maintenance ensures that software continues to function correctly, securely, and efficiently as user requirements and technology change.

### **Why is Software Maintenance Required?**

- Fix production bugs.
- Improve application performance.
- Resolve security vulnerabilities.
- Add new features.
- Update dependencies.
- Improve user experience.
- Support new operating system versions.
- Maintain compatibility.
- Adapt to changing business requirements.

### **Types of Software Maintenance**

**1. Corrective Maintenance**

Fixing existing errors and defects.

Example: Fixing an incorrect salary calculation.

**2. Adaptive Maintenance**

Updating software to work with a changed environment.

Example: Updating an application to support a new operating system.

**3. Perfective Maintenance**

Improving existing features and performance.

Example: Improving dashboard loading speed.

**4. Preventive Maintenance**

Making changes to reduce the possibility of future problems.

Example: Refactoring poorly structured code and updating outdated dependencies.

### **Real-World Example**

A company uses an Employee Management System.

After deployment:

- Employees report login problems.
- HR requests a new report.
- Managers request additional dashboard filters.
- Security vulnerabilities are identified.
- The application becomes slower as employee records increase.

The development team fixes these issues and releases updated versions.

**Note:** Software development does not end after deployment. Maintenance is an ongoing activity throughout the software's useful life.

## **115. What are Software Development Methodologies?**

### **Definition**
Software Development Methodologies are structured approaches, frameworks, and practices used by software development teams to organize, plan, develop, test, and deliver software projects.

They define how teams manage project activities, communicate, handle requirements, and deliver software.

### **Why are Development Methodologies Required?**

- Organize development activities.
- Improve team collaboration.
- Manage project schedules.
- Control project risks.
- Improve software quality.
- Handle changing requirements.
- Track development progress.
- Support timely delivery.

### **Types of Software Development Methodologies**

1. Waterfall Methodology
2. Agile Methodology
3. Scrum Framework
4. Kanban Methodology
5. Spiral Model
6. Iterative Development
7. Incremental Development
8. V-Model
9. Prototype Model
10. Extreme Programming (XP)
11. Lean Software Development
12. DevOps Approach

### **Comparison of Development Methodologies**

| Methodology | Main Approach | Suitable For |
|---|---|---|
| Waterfall | Sequential development | Stable requirements |
| Agile | Iterative and adaptive development | Changing requirements |
| Scrum | Time-boxed Sprints | Collaborative teams |
| Kanban | Continuous workflow | Ongoing tasks |
| Spiral | Risk-driven development | Complex projects |
| V-Model | Development and corresponding testing | High-assurance projects |
| XP | Engineering practices and frequent feedback | Rapid software development |
| Lean | Reduce waste and improve value | Process optimization |

### **Example**

A company wants to build a banking application.

The team can select a methodology based on:

- Project size.
- Business requirements.
- Security requirements.
- Team experience.
- Delivery timeline.
- Customer involvement.
- Regulatory constraints.

**Note:** No single methodology is best for every project. The development team should select an approach based on project requirements, complexity, risk, and business goals.

## **116. What is Agile and Scrum?**

### **Part A: What is Agile Methodology?**

**Definition**

Agile is an iterative and incremental approach to software development in which teams deliver software in smaller portions, receive regular feedback, and adapt to changing requirements.

Instead of waiting until the entire application is completed, teams develop and deliver working functionality in smaller increments.

### **Why is Agile Used?**

- Supports changing requirements.
- Encourages customer collaboration.
- Delivers software frequently.
- Improves team communication.
- Identifies problems early.
- Encourages continuous improvement.
- Provides better project visibility.

### **Agile Principles**

1. Deliver working software frequently.
2. Welcome changing requirements.
3. Encourage customer collaboration.
4. Promote continuous communication.
5. Focus on working software.
6. Improve development processes continuously.
7. Encourage self-organizing teams.

### **Part B: What is Scrum?**

**Definition**

Scrum is an Agile framework that helps teams develop, deliver, and improve products through short, fixed-length iterations called Sprints.

A Sprint commonly lasts one to four weeks.

### **Scrum Roles**

**1. Product Owner**

- Defines product goals.
- Manages the Product Backlog.
- Prioritizes requirements.
- Communicates business needs.

**2. Scrum Master**

- Helps the team understand Scrum.
- Facilitates Scrum events.
- Removes or helps resolve impediments.
- Supports continuous improvement.

**3. Developers**

- Design the solution.
- Write source code.
- Test functionality.
- Deliver working product increments.

### **Scrum Events**

1. Sprint Planning.
2. Daily Scrum.
3. Sprint Review.
4. Sprint Retrospective.

### **Scrum Artifacts**

1. Product Backlog.
2. Sprint Backlog.
3. Increment.

### **Important Agile and Scrum Terminologies**

| Term | Explanation |
|---|---|
| Sprint | Fixed-length development cycle |
| User Story | Requirement described from the user's perspective |
| Product Backlog | Ordered list of product work |
| Sprint Backlog | Work selected for a Sprint |
| Daily Scrum | Short daily team synchronization |
| Story Points | Relative estimation of work |
| Velocity | Amount of work completed in a Sprint |
| Epic | Large body of related work |
| Bug | Defect in software |
| Retrospective | Meeting to improve the team's process |

### **Real-World Example: Employee Management System**

A team is developing an employee management application.

**Sprint 1:**
- Login page.
- Authentication.
- User roles.

**Sprint 2:**
- Employee registration.
- Employee listing.
- Employee profile.

**Sprint 3:**
- Attendance management.
- Leave requests.
- Leave approval.

**Sprint 4:**
- Dashboard.
- Reports.
- Performance improvements.

After each Sprint, the team reviews completed functionality and plans the next Sprint.

**Note:** Agile is an approach to software development, whereas Scrum is a framework that implements Agile principles through defined roles, events, and artifacts. Agile and Scrum are related but are not the same thing.

## **117. What is Version Control?**

### **Definition**
Version Control is a system used to track, manage, and maintain changes made to source code and other project files over time.

It allows developers to view previous versions, collaborate with team members, compare changes, and restore earlier versions when necessary.

### **Why is Version Control Required?**

- Tracks source code changes.
- Maintains project history.
- Supports multiple developers.
- Prevents loss of work.
- Helps identify who changed the code.
- Supports collaboration.
- Enables branching and merging.
- Helps recover previous versions.

### **Types of Version Control Systems**

**1. Local Version Control**

Maintains file versions on an individual computer.

**2. Centralized Version Control (CVCS)**

Stores version history in a central server.

Examples:
- Apache Subversion (SVN).
- Perforce Helix Core.

**3. Distributed Version Control (DVCS)**

Provides developers with local copies of the repository and its version history.

Examples:
- Git.
- Mercurial.

### **Important Version Control Terminologies**

| Term | Explanation |
|---|---|
| Repository | Location where project files and history are maintained |
| Commit | Recorded set of changes |
| Branch | Separate line of development |
| Merge | Combining changes from different branches |
| Clone | Creating a local copy of a repository |
| Pull | Fetching and integrating remote changes |
| Push | Uploading local commits to a remote repository |
| Fetch | Downloading remote repository updates |
| Conflict | Incompatible changes that require resolution |
| Checkout | Switching branches or restoring files, depending on the command |
| Staging | Preparing changes for a commit |

### **Real-World Example**

Suppose three developers are working on an Employee Management System.

- Developer 1 works on the login page.
- Developer 2 works on the employee dashboard.
- Developer 3 works on attendance management.

Using Version Control:

1. Each developer creates a separate branch.
2. Each developer writes code independently.
3. Each developer commits changes.
4. Developers push their branches.
5. The team reviews the changes.
6. Approved changes are merged into the main branch.

**Note:** Version Control is essential in professional software development because it maintains code history, supports collaboration, and reduces the risk of losing important project changes.

## **118. What are Git and GitHub?**

### **Part A: What is Git?**

**Definition**

Git is a free, open-source, distributed version control system used to track changes in source code and manage software development projects.

It allows developers to maintain project history, create branches, compare changes, and collaborate with other developers.

### **Why is Git Used?**

- Track code changes.
- Maintain commit history.
- Create development branches.
- Merge code changes.
- Restore previous versions.
- Support team collaboration.
- Work without a continuous internet connection.

### **Important Git Commands**

| Git Command | Purpose |
|---|---|
| `git --version` | Check Git installation |
| `git config` | Configure Git settings |
| `git init` | Initialize a repository |
| `git clone` | Copy an existing repository |
| `git status` | Check working directory status |
| `git add` | Stage changes |
| `git commit` | Save staged changes |
| `git log` | View commit history |
| `git branch` | List or manage branches |
| `git checkout` | Switch branches or restore files |
| `git switch` | Switch branches |
| `git merge` | Merge branches |
| `git pull` | Fetch and integrate remote changes |
| `git push` | Upload commits to a remote repository |
| `git fetch` | Download remote updates |
| `git diff` | Compare changes |

### **Basic Git Workflow**

```text
Working Directory
       |
       v
   git add
       |
       v
  Staging Area
       |
       v
  git commit
       |
       v
 Local Repository
       |
       v
   git push
       |
       v
Remote Repository
(GitHub or another Git server)
```

### **Part B: What is GitHub?**

**Definition**

GitHub is a cloud-based platform for hosting Git repositories and collaborating on software development projects.

It provides tools for managing source code, reviewing changes, tracking issues, and coordinating development work.

### **Why is GitHub Used?**

- Host source code online.
- Share projects with developers.
- Collaborate with teams.
- Maintain project documentation.
- Review code changes.
- Track bugs and feature requests.
- Manage Pull Requests.
- Build a developer portfolio.

### **Important GitHub Features**

1. Repositories.
2. Branches.
3. Commits.
4. Pull Requests.
5. Issues.
6. Discussions.
7. GitHub Actions.
8. Releases.
9. README Files.
10. GitHub Pages.
11. Code Review.
12. Project Boards.

### **Part C: Difference Between Git and GitHub**

| Git | GitHub |
|---|---|
| Version control system | Git repository hosting and collaboration platform |
| Installed and used locally | Primarily accessed online |
| Tracks source code changes | Hosts and manages repositories |
| Works offline | Online features require internet |
| Developed initially by Linus Torvalds | Launched by GitHub in 2008 |
| Uses Git commands | Provides a web interface and collaboration features |

### **Part D: How to Use Git and GitHub Together**

**Step 1: Install Git**

Download Git from:

https://git-scm.com/

**Step 2: Create a GitHub Account**

https://github.com/

**Step 3: Configure Git**

```bash
git config --global user.name "Your Name"
git config --global user.email "your@email.com"
```

**Step 4: Create a Project Folder**

```bash
mkdir employee-management-system

cd employee-management-system
```

**Step 5: Initialize Git**

```bash
git init
```

**Step 6: Create a README File**

```bash
echo "# Employee Management System" > README.md
```

**Step 7: Check Project Status**

```bash
git status
```

**Step 8: Stage Changes**

```bash
git add .
```

**Step 9: Commit Changes**

```bash
git commit -m "Initial project setup"
```

**Step 10: Create a Repository on GitHub**

Open GitHub and create a new repository named:

`employee-management-system`

**Step 11: Connect Local Repository to GitHub**

Replace the URL with your actual GitHub repository URL.

```bash
git remote add origin https://github.com/USERNAME/employee-management-system.git
```

**Step 12: Push Code to GitHub**

```bash
git branch -M main

git push -u origin main
```

Suppose a software development team has five developers.

| Developer 3 | Employee management |
| Developer 4 | Attendance management |

The team follows this workflow:

1. The project manager creates development tasks.
2. Developers clone the GitHub repository.
3. Each developer creates a separate branch.
4. Developers implement their assigned features.
5. Developers commit their changes.
6. Developers push branches to GitHub.
7. Developers create Pull Requests.

**Note:** Git and GitHub are essential tools for modern software development. Git manages version history, while GitHub provides a platform for hosting repositories and collaborating with development teams.
